# 两套可直接运行的引擎：FD-1 双通道 + P6 v2

最后更新：2026-11-03（数据截至 2026-11-01 收盘）
适用对象：第一次拿到本仓库的人或 AI。只要把日线 K 线喂进 `cache_fresh/`，按下面的命令就能跑；不需要数据库、不需要 API key、不需要 pandas。

---

## 0. 30 秒快速开始

```bash
# 1) 依赖：Python 3.10+，numpy
pip install -r systems/requirements.txt

# 2) 把 K 线转成引擎格式（CSV 或已有 JSON 都行）
python systems/prepare_data.py --input /path/to/kline.csv --out cache_fresh
#    或：python systems/prepare_data.py --input /path/to/kline_dir --out cache_fresh

# 3) 跑两套引擎的当日扫描
V2_CACHE=/abs/path/to/cache_fresh python systems/fd1/strategy.py
V2_CACHE=/abs/path/to/cache_fresh python systems/p6/rs_scan.py

# 4) 生成本地看板（只写本地 HTML，不发布）
V2_CACHE=/abs/path/to/cache_fresh python systems/fd1/board.py
V2_CACHE=/abs/path/to/cache_fresh python systems/p6/board.py
```

两套引擎共用 `v2/engine/v2_lib.py` 的数据加载、特征、组合模拟；**P6 还依赖 `systems/fd1/` 里的 `strategy.py`、`variants.py`、`portfolio.py`，两个目录要一起保留**。

## 1. 数据契约（最重要）

### 1.1 目录格式

```
cache_fresh/
  AAPLUSDT.json
  NVDAUSDT.json
  TSLAUSDT.json
  ...
```

每个文件是该标的的日线数组，按时间升序：

```json
[
  {"time": "2026-10-30", "open": 338.1, "high": 346.2, "low": 337.0, "close": 345.1, "volume": 1234567.0},
  {"time": "2026-11-01", "open": 345.1, "high": 348.0, "low": 342.2, "close": 346.5, "volume": 987654.0}
]
```

字段：
- `time`：`YYYY-MM-DD`（日线）。引擎按自然日对齐，7×24 每自然日一根，不是美股交易日。
- `open/high/low/close`：正数；建议用未复权或前复权都可以，但同一标的全历史必须一致。
- `volume`：基础币/股成交量（不是成交额）；`dv20` = `close × volume` 的 20 日中位数。

### 1.2 最少根数

- 引擎有 210 / 220 根 warmup；**每个标的至少 260 根**才有意义。
- 少于 210 根的标的不会产生信号；`prepare_data.py` 会给出 WARN。

### 1.3 标的范围

- 引擎读取 `cache_fresh/` 下**所有** `*.json`，不依赖外部池文件。
- 参考结果使用 120 只核心个股（144 个标的里剔除 24 个杠杆/ETF；代码里 `v2_lib.ETF` / `v2_lib.LEV` 会自动剔除）。
- 想复现参考统计，就喂同样的 120 只；只喂 10 只也能跑，但统计会变。

### 1.4 数据清洗

`v2_lib.load_all()` 会自动做：
- 丢弃 open/close 为空的 bar；
- 对“价格尺度跳变”（如 167 → 658 → 195）做段剔除；
- 对单边向上 >40% 的跳变做前复权；
- 对 `|ret| > 35%` 的 bar 标记 `jump`，不参与入场和止损/止盈触发。

**不要把已经复权/清洗过的数据再手工改一遍**；直接把原始日线喂进来即可。`prepare_data.py` 只做格式转换和同日聚合，不做复权。

### 1.5 成交与成本假设

- 收盘出信号，**下一根工作日开盘**成交；周五信号等周一。
- 5x 逐仓；单笔保证金 = 权益 × 3%（名义 = 权益 × 15%）。
- 最多 16 个同时持仓；总毛敞口 ≤ 2.5 × 权益；P6 同日最多 5 个新仓。
- 手续费 + 滑点 0.20% 往返；资金费 0.03%/日；5x 爆仓距离约 19%。
- 同一根 bar 内止损与止盈都触及时，回测按**先止损**处理（保守）；跳空按开盘价成交。

## 2. FD-1 双通道（`systems/fd1/`）

### 2.1 一句话逻辑

通道 A 做“上升趋势里的深踩”：收盘仍在 MA100 上方、MA100 斜率不为负，20 日偏离 ≤ −5%、RSI2 ≤ 30 时买入。通道 B 做“上升趋势里的 20 日新高放量突破”：收盘创 20 日收盘新高、当日量 ≥ 2 倍 20 日中位量、仍在 MA100 上方。两条通道共用 +0.9 ATR 止盈、−1.5 ATR 止损、最多 5 根日线（2026-11-04 由 0.8 上调，出场全扫描里唯一走前不塌的档）。

### 2.2 精确规则

**通道 A · 深踩**（全部满足）：
- 收盘 > MA100，且 MA100 的 20 日斜率 ≥ 0；
- `close / MA20 - 1 ≤ −5%`；
- RSI2 ≤ 30；
- 收盘 ≥ 5；20 日成交额中位数 ≥ 3000 万美元；ATR% ≤ 6%；
- 只做个股（剔除 ETF/杠杆）；至少 210 根历史；非数据跳变。

**通道 B · 20 日新高放量突破**（全部满足）：
- 收盘 > 过去 20 根收盘最高（不含当日）；
- 当日成交量 ≥ 2.0 × 过去 20 日中位量；
- 收盘 > MA100，且 MA100 的 20 日斜率 ≥ 0；
- 收盘 ≥ 5；20 日成交额中位数 ≥ 3000 万美元；ATR% ≤ 6%；
- 只做个股；至少 210 根历史；同一标的 10 根内只取第一次。

**出场（两通道共用）**：
- 止盈 `entry + 0.9 × ATR14`；
- 止损 `entry − 1.5 × ATR14`；
- 最多 5 根日线，到期按收盘；
- 跳空：开盘低于止损按开盘，开盘高于止盈按开盘。

### 2.3 参考统计（asof 2026-11-03，120 只个股，5x/3%/16/2.5x，止盈 0.9）

| 口径 | 笔数 | 胜率 | PF | 年化 | 最大回撤 |
|---|---:|---:|---:|---:|---:|
| 双通道 全样本 | 509 | 68.0% | 1.57 | 45.1% | 13.03% |
| 双通道 2026-01-26 起（真实段） | 146 | 69.9% | 2.05 | 53.7% | 4.86% |
| 深踩单通道 全样本（对照） | 264 | 67.4% | 1.59 | 22.3% | 8.53% |
| 深踩单通道 2026-01-26 起（对照） | 65 | 66.2% | 1.81 | 16.6% | 4.24% |

止盈 0.9 相对 0.8 的账（同一引擎、同一数据，`build_report.json` 可复算）：全样本笔数 519→509，胜率 70.7%→68.0%，PF 1.49→1.57，年化 36.7%→45.1%，回撤 12.46%→13.03%；2026 段 147→146，72.8%→69.9%，PF 1.78→2.05，年化 34.7%→53.7%，回撤 5.35%→4.86%。收益提升主要来自跳空开盘直接越过 0.9 的 78 笔（逐笔均值 +1.54%）；非跳空子集统计上接近零（自助法 P(均值>0)=48.1%）。真正稳的理由是结构：盈亏比 0.70→0.84，打平胜率 58.7%→54.3%，安全垫 +13.7pp→+15.2pp。回退触发（前向 40 笔内）：胜率 < 62%、跳空止盈 0 笔、或亏超 −8% 的笔数占比 > 12%，任一出现就把 `TP_ATR` 改回 0.8。

## 3. P6 v2（`systems/p6/`）

### 3.1 一句话逻辑

不设全市场闸门，只看个股自己的趋势、强度和量能：站上 MA50 且 MA50 > MA100、两条均线都向上、20 日收益为正，并且信号日成交量 ≥ 1.5 × 20 日中位量时买入；+0.8 ATR 止盈、−1.8 ATR 止损、最多 7 根日线。**只在状态第一次从 false 变 true 时入场；一个上涨段只做一次。**

### 3.2 精确规则

**入场**（全部满足）：
- 收盘 > MA50 > MA100；
- MA50 的 10 日斜率 ≥ 0；MA100 的 20 日斜率 ≥ 0；
- 20 日收益 > 0（绝对强度，不要求跑赢指数）；
- 信号日成交量 ≥ 1.5 × 20 日中位量；
- 收盘 ≥ 5；20 日成交额中位数 ≥ 3000 万美元；ATR% ≤ 6%；
- 只做个股；至少 220 根历史；非数据跳变；
- 首次触发：今天满足且昨天不满足；平仓后要等状态 reset 再重新计数。

**出场**：
- 止盈 `entry + 0.8 × ATR14`；
- 止损 `entry − 1.8 × ATR14`；
- 最多 7 根日线；跳空按开盘；同 bar 先止损。

| 全样本 | 653 | 29.7 | 70.0% | 1.17 | +32.5% | +16.6% | −14.39% |
| 2025-06-01 起 | 581 | 34.2 | 71.4% | 1.27 | +48.1% | +31.9% | −12.45% |

2026-01-26 起（研究 `sim_port` 口径）：217 笔 / 73.7% / PF1.47 / 年化 +41.8% / 回撤 7.11%。

## 3b. 起涨点两套（`systems/rally_u/`、`systems/rally_cold/`，本地未上线）

两套共用同一套「洗盘弹簧」入场与出场（50% 在 +12%、50% 在 +30%、连续 3 根收盘破 60 日低走、−30% 灾难上限、最多 60 根；1% 权益风险/笔、5x、16 仓、同日 5 仓、毛 ≤2.5x），区别只在市场级条件与是否有模型分。

### U 平衡（`systems/rally_u/`，无模型分）

- 入场层：A 质量版（`dev20 ≤ −8%`、RSI2 ≤ 40、ATR ≥ 6%、跌破前 10 日低、量比 ≥ 0.8，5 根内收回、收盘位置 ≥ 0.4）+ B+ 覆盖版（−5%/50/4%/0.5，8 根内收回、收阳），合并去重 A 优先。
- 市场层：120 只个股宽度 ≤ 34%；个股层 A 当日振幅 ≥ 7%、B 当日涨幅 ≥ 7%。
- **集群确认（2026-11-05 加严）**：同日 A 信号 ≥ 3 **且** 同日 B 信号 ≥ 20。家数一律从固定起点 `FIX_SCAN_I0 = 220` 根扫描后计数，与 `start_date` 无关，收盘可复现。
- 加严前后（组合口径，100,000 起始）：2025-03-01 起 52 笔 / 69.2% / PF1.42 / +9.63% / 回撤 −29.36% → 29 笔 / 89.7% / PF10.12 / +30.62% / 回撤 −9.29%；2025-06-01 起 22 笔 / 95.5% / +28.41% / −4.53% → 14 笔 / 100% / +19.39% / −3.92%；2026-01-01 起 12 笔 / 91.7% / +13.41% / −1.99% → 5 笔 / 100% / +5.49% / −1.09%。2025-03 入场 33 笔（−388.8%）→ 5 笔（−16.2%）。
- **代价**：B ≥ 20 是极低频事件。全样本满足的日子只有 2025-03（2 天）、2025-04（4 天）、2025-11（3 天）、2026-02（2 天）、2026-03（3 天）；最近 90 个交易日 concB 最大 6，所以 2026-05-01 起 0 笔。它是「一天内全场被卖才出手」的事件型系统。
- 跑：`V2_CACHE=<work>/cache_fresh python systems/rally_u/board.py`（页面 + `build_report.json`）；`backtest.py` 写 `backtest_report.json` + `signals.csv`；`scan.py` 只看最近信号。

### 冷启动 · 全历史起涨（`systems/rally_cold/`，带模型分）

- 模型：22 个因果特征，L2 逻辑回归，起涨事件日等权；每季度只用该季度之前的数据重训；2025-03 那批分数只用 < 2025-03-01 的数据训练。
- 门槛（2026-11-05 改甲）：**全程模型分 ≥ 0.75**，不再有「3/4 月 0.75、5 月起 0.65」的日历分支。
- 结构闸门：宽度 ≤ 35%；同日 A ≥ 3；个股当日振幅 ≥ 7% 或涨幅 ≥ 7%；同标的 5 根去重。
- 改甲前后（组合口径）：2025-03-01 起 58 笔 / 77.6% / PF3.64 / +44.17% / 回撤 −9.33% → 49 笔 / 81.6% / PF4.07 / +38.99% / 回撤 −9.33%；2025-06-01 起 44 笔 / 75.0% / +33.66% / −6.66% → 35 笔 / 80.0% / +28.87% / −6.15%；2026-01-01 起 29 笔 / 75.9% / +22.87% / −5.97% → 21 笔 / 90.5% / +18.82% / −4.63%。逐笔 128 笔 / 84.4% / PF11.32 → 106 笔 / 85.8% / PF10.55。**2025-03 入场 0 笔**（3 月信号最高分只有 0.742）。
- 已知边界：门槛与 3 月最高分之间只有 0.008 的余量，挡 3 月这件事在整个代币数据里只有一次事件；门槛调整必须走前向判据，禁止改成按日期禁止开仓。
- 跑：`V2_CACHE=<work>/cache_fresh python systems/rally_cold/board.py`（约 2—3 分钟，含季度走前训练）。

### 为什么这两套的闸门不一样

U 没有模型分，唯一能挡住阴跌的市场级条件就是集群家数；冷启动有模型分，统一分数门槛就能把 3 月挡掉且几乎不掉收益。同一条「集群 ≥ 18/20」的闸**不能**搬到 FD-1 或 P6：实测 FD-1 的 2025-06..12 年化从 92.1% 掉到 29.6%（A≥3）/17.1%（A≥18），P6 全期总收益从 +36.0% 掉到 +2.6%。

## 6. 已知限制与风险

- 2026-01-26 之前的日线包含回填/合成段；2025 年数据权重低。真实合约段样本薄，任何高 PF 都不应外推。
- 5x 杠杆下，历史回撤 ≠ 未来最大回撤；跳空可能显著超过止损。
- 只做多；系统性下跌时两套都会连续止损；仓位上限和止损是唯一保护。
- 这是研究代码，不是投资建议，也不是自动交易系统；上线前必须自己做前向验证。
- `board.py` 生成的 `index.html` 先写本地；只有在用户明确要求发版时才提交。`build_report.json` 里的 `page_sha256` 是本地页面哈希，上传后可用 contents API 回读逐字校验。GitHub Pages 站点（`v2/`、`firstleg/`）与 `systems/` 目录是两条独立的路，本次只动 `systems/`。
