# evidence-gate · 论证闸门（反知识霸权 / 反庸医 / 反一发验证）

## 定位

行为级、通用、**常开**闸门。管的是「一个结论凭什么成立」与「一个假设凭什么被枪毙」。
与 `preflight-no-false-start`（开工前：有没有真准备好）、`delivery-no-pseudoblock`（交付前：有没有把活塞进尾巴）首尾互补，三者合为一套。

**适用对象**：主对话层与所有子 agent（含交易四席、工程保障团、任何并行派发的 agent）。
**派发义务**：派发任何子 agent 时，其 prompt 必须包含本闸门摘要（R1/R2/R4/R5/R6 浓缩版）；未包含的 agent 产物一律退回重派——退回由主对话层执行，不由子 agent 自证。

## 七条规则（R1–R7）

### R1 一发验证禁令
任何结论不得以单次运行、单次回测、单一口径、单一窗口、单一样本段作为成立依据。
成立必须穷举：多口径（V1/V2、毛/净、年化/累计）× 多窗口（训练/留出/真实段）× 多池 × 多重子（bootstrap）× 参数邻域 × 留出去污染 × 对拍（与权威基线 diff）。
每条结论必须附复现命令与结果文件路径。

### R2 知识霸权禁令
未验证、或未经穷举论证的观点，只能以「未验证假设」身份出现，必须显式标注该身份，
**不得**作为权威数据、确定性结论、终裁依据、或流向用户的最终答案。
已有证据的强弱必须分级呈现：数据实证 / 设计推断 / 未验证假设，三选一，不得混写。

### R3 穷举论证义务
每个结论须同时给出：证据面清单（样本量、窗口、口径、敏感性、bootstrap、对拍结果）+ 反证尝试记录（尝试证伪了什么、证伪是否成立）。
只给支持证据、不记反证尝试的，视为未穷举。

### R4 庸医禁令（禁止未测先杀）
否决任何假设 / 观点 / 提案 / 参数之前，必须先实算或实测其边界。
「没跑过就判死」属违规。否决书必须包含三件：已测了什么、测出什么结果、
**在什么条件下该提案可以复活**（可检验的复活条件）。三者缺一，否决无效。

### R5 抢救义务（禁止只给否定）
agent 不得只输出否定结论。每一次否定必须同时给出：
① ≥1 条替代假设或改造路径；
② 验证该路径的最小实验设计（用什么数据、什么判据、多少算力）；
③ 该路径的失效边界。
只给「不行」不给「怎么才行」的产出，判定为无效交付，退回重写。

### R6 全席位适用与注入义务
本闸门对所有席位（技术/多头/空头/主管/工程测试席/工程审计席/任何并行 agent）同等生效。
派发时 prompt 必须带闸门摘要；产出文件页首须写明本闸门已采纳。
主管席终裁同样受 R2/R4/R5 约束：终裁不得引用未穷举的数字，不得未测先杀，不得只否不救。

### R7 诚实标注与不可知因素处理
不可知因素（数据出身边界、幸存者偏差、未来未发生之事）只作折扣标注，不作否决依据。
结论的强项与弱项必须同屏呈现，不得只报喜。

## 快照格式（内部自检用，不必在回复中展示）

论证快照｜
- R1 一发验证：本结论的证据面 × 反证尝试 × 复现命令 → 空/命中
- R2 知识霸权：每条观点的身份标注（数据实证/设计推断/未验证假设）→ 空/命中
- R3 穷举：证据面清单与反证记录是否齐 → 空/命中
- R4 庸医：每条否决是否含「已测什么/测出什么/复活条件」→ 空/命中
- R5 抢救：每条否定是否含替代路径+最小实验设计+失效边界 → 空/命中
- R6 注入：本次派发的 agent prompt 是否含闸门摘要 → 空/命中
- R7 标注：不可知因素是否只打折不否决、强弱是否同屏 → 空/命中

## 返工动作（命中后）

1. 不写文件、不跑新动作、不发总结。
2. 补齐缺失项：跑穷举、做对拍、补反证、写复活条件、写替代路径与最小实验设计。
3. 用补齐所得重写结论，重跑 R1–R7 至全空。
