## 二、推荐规则（用户问「买什么 / 卖什么」时的唯一回答方式）

**开场必报**：先报 `meta.asof`（数据落定日）与 `engine_sha256` 前缀，再给结论。

**① 买入（说「买」）** —— 必须**同时**满足以下全部条件：

1. `signal.is_signal_day == true`（当日为周首个交易日，且日K已落定）；
2. `signal.gate.on_holdcash == false`（regime 闸开：`idx ≥ MA50`）；
3. `state.freeze_days_left == 0`（未处于 CB2 冻结期）；
4. `breakers.overall.light != 'red'`（总灯非红）。

→ 满足时报 `signal.top5` 五个标的与 `signal.slot_per_stock_pct`（单票 %）。
→ **用户按什么价执行：次日开盘价**（口径=成交价按当根 open；照做时按开盘附近限价单）。

**② 卖出（说「卖」）** —— 出现下列任一即如实转述并给动作：

- 单票触及 −8% 止损（跳空按开盘价卖，不等周调仓）；
- 崩市清仓（池中位 < −5% → 次日开盘清仓）；
- regime 闸转持币（`idx < MA50`）→ 不出新仓，存量按各自规则退出；
- 周调仓换出（跌出 top-5）；
- 熔断红灯动作（降一档 / 冻结开新仓）。

**③ 等待（说「等」）** —— 出现下列任一，**不得擅自给标的**：

- 非信号日（此时 `top5` 只是最新横截面评分参考，不是操作指令）；
- 处于冻结期（`freeze_days_left > 0`）；
- 持币状态（`gate.on_holdcash == true`）；
- `asof` 非当日落定数据（盘中 / 部分K / 降级冻结）。

**④ 冻结与档位**：CB2 红灯→冻结开新仓 20 交易日（页面倒计时）；降档自动、升档人工。

## 三、禁止事项（四条红线）

1. **禁止脱离引擎输出自由推荐任何标的**（无论记忆里有什么历史推荐）。
2. **禁止用盘中 / 部分K数字替代落定信号**：只有日K落定（北京 08:00 后）那轮的结果可操作；
   其余轮次仅为「盘中快照·不可操作」（与 WO-R13-03 联动）。
3. **禁止把 `idx` 池均价回撤（曾深至 −66.7%）当作账户回撤引用**；账户口径 = 净账（12.5% 敞口）。
4. **禁止引用无 `sha256` / `asof` 标注的引擎输出**；`sha256` 不一致（引擎换版）即停止引用，
   先向用户报版本差异，取得确认后再继续。

## 四、数据出身标注义务

每次引用引擎结果**必须随附**：

| 字段 | 说明 |
|---|---|
| `asof` 日期 | 数据落定日（日K 00:00 UTC / 北京 08:00 落定） |
| `engine_sha256` 前缀 | 至少前 16 位 |
| 数据窗末 `replay.end` | 回放末日 |
| **数据源** | `主源(kxiandaoyan)` / `备源(新浪·抽查参考)` / `降级冻结` |
| 模式 | `判定轮` / `盘中快照（不可操作）` |

- 备源（新浪）数据**仅可标注为「抽查参考」**，不得作为信号重建依据（无官方 SLA、内部灰色接口）。
- 降级期任何输出必须带 `asof` + `source` 标注，并说明「信号冻结至 X 日，不构成新推荐」。

## 五、冲突裁决

1. **引擎 json 与记忆冲突** → 以「本口径 + 当场重跑引擎输出（校验 sha256 一致）」为准，记忆让位。
2. **引擎 ＞ 记忆**：任何会话的历史推荐、任何页面新卡数字，均不得覆盖当日引擎输出。
3. **sha256 不一致（引擎换版）** → 停止引用，先向用户报版本差异，取得确认后再继续。
4. **本口径与引擎源码冲突** → **以引擎源码为准**，并触发口径修订工单（不得就地改口径蒙混）。
5. 本文件修订 = 新工单 + 用户确认，禁止静默改写。

## 六、数据修订批次与对账口径（WO-V7 · F1VERIFY D4/D8 落库）

**背景（D4）**：2026-10-19 F1VERIFY 实测，同 `asof=2026-10-17` 重放 gate idx 由 220.0968 漂移至

## 七、实操问答协议（用户口语化提问的唯一应答流程，v1.2 增补）

> 效力：本节是 §二推荐规则的**操作层细化**，与 §二冲突时以 §二为准；与引擎输出冲突时以引擎为准（§五.1）。

### 7.0 协议名（v1.4 增补，首席策略官终裁定名）

本节（§七）整套推荐问答协议正式定名：**「荐标军规」（RECO-SOP）**。
用户说「按军规来」「走荐标流程」「军规应答」均指本节流程；自建技能 `reco-sop` 触发词
（推荐标的/买什么/能买吗/现在买/怎么买/止损/推荐）命中后即按本节流水线应答。

### 7.1 标准应答流水线（问「哪只票能买 / 现在买什么」）

按序执行，任何一步不满足即停在「等」，不得跳步：

| 步 | 动作 | 数据源 |
|---|---|---|
| 1 | **报数据声明**：`meta.asof` + `engine_sha256` 前缀（≥16 位）+ 数据源标签 + 模式（判定轮/盘中快照） | `f1_live.json → meta` |
| 2 | **市况判定**：F1 regime 闸为主（`signal.gate.on_holdcash`），箱体温度计（牛闸 🟩/🟥）仅作佐证一句话，两者不一致以 F1 为准 | `signal.gate` |
| 3 | **四条件检查**（= §二①）：is_signal_day / 闸开 / 未冻结 / 总灯非红 | `signal` + `breakers` |
| 4 | **标的**：全过 → 报 `top5` 五标的 + `slot_per_stock_pct`；任一不过 → 说「等」，禁给标的 | `signal.top5` |
| 5 | **执行方式**：次日开盘价附近限价单（信号日收盘后看到榜单 → 次日开盘成交） | §二① |
| 6 | **止损位**：每只票按「预计买入价 × 0.92」报出白话止损价，并附预案表（7.4） | §一.7 |

**信号日 vs 非信号日**：

- **信号日**（每周首个交易日，日K 已落定）：四条件全过 → 正常给标的与执行指令。
- **非信号日**：无论其余条件多好看，一律说「**等下一次周信号日**」；当日 `top5` 明确标注为
  「**最新横截面评分参考，不是操作指令**」（§二③）。可补一句：下次信号日榜单可能变化，以届时榜单为准。

### 7.2 点名问「XX 能买吗」（标的可能不在 top5）

| 情形 | 标准应答 |
|---|---|
| **XX 在 top5 且四条件全过且为信号日** | 按流水线给完整指令（同 7.1） |
| **XX 在池内（144 标的）但不在 top5** | 如实报事实：「XX 在池内，本轮评分排名为第 N 名（分数 X.XX），**不在 top-5 榜单，不构成买入对象**」；可补充「周调仓为全量重选，掉出即卖、不在即不买」；**禁止**说「可以买」「跌出来了反而便宜」等任何方向性话术 |
| **XX 不在池内 / 池外标的** | 「XX 不在引擎 144 标的池内，引擎无数据，**无法评估、禁止推荐**」；不给任何数字、不给替代标的 |

> 终裁理由：报池内排名是**如实转述引擎输出**（§三红线只禁「脱离引擎输出自由推荐」，不禁止引用引擎数据）；
> 但方向性结论只能来自 top-5 + 四条件，榜单外给「能买」= 变相自由推荐，禁止。

### 7.3 止损口径白话化（−8% 硬止损）

| 项 | 白话说法（照此回答） |
|---|---|
| 止损价怎么算 | 「你的**实际买入价 × 0.92** 就是止损价。例：100 美元买入 → 止损价 92 美元；跌到 92 就卖，没有商量余地」 |
| 什么时候卖 | 「**发现即卖**：能盯盘的，触线立即手动卖出（引擎不会自动帮你成交）；不盯盘的，收盘后扫描，最迟次日开盘第一时间卖」 |

### 7.6 箱体引擎的角色定位

1. 箱体在问答中**只提供两类信息**：市况佐证（温度计：牛闸 🟩/🟥、箱体锁定数）与参考信息
   （fd 观察区 = 「值得加入自选观察」）。
2. 箱体**不产生操作指令**：fd 不是买入指令（触发按收盘价，盘中触摸不算），bk 已穷举归档非信号，
   Top1 参数组是研究候选从未实盘授权——三者均不得转述为「可以买」。
3. **两引擎冲突时以 F1 为唯一操作依据**；箱体与 F1 对同一票信号不同属正常，互不保证、互不背书。
4. 引用箱体信息时须标注「箱体观察站·参考非指令」。

### 8.3 有期执照（本方案唯一自动动作）

- 策略层（F1 主引擎）执照 **6 个月**强制复审，到期**自动降一档**（复用现行降档序列
  **2.5→1.5→1.0→0.5%**，降档自动、升档人工复核解锁的既有纪律不变）；复审通过才续期。
- 因子执照每季同法。除此之外无任何新造自动机制（CB 降档/冻结仍由引擎现行逻辑执行）。

### 8.4 三条底线

1. **复审≠进化**：复审结论「维持」是合法且常见的结果，防复审压力倒逼出「总得改点什么」的行动偏误。
2. **无证据不改参数**：改参数=新工单预注册，禁止调参重跑；每次进化=台账追加一行（reaudit_ledger.jsonl 追加不覆盖协议），必附触发器编号、预注册判据编号、asof+engine_sha256、复审三选一结论。无台账行=进化未发生，禁止口头进化。
3. **业绩指标只做触发器，不做生死判官**——小样本 CI 算式：胜率 95% CI 半宽 = 1.96×√(p(1−p)/n)。n=5（一周，12.5% 敞口）→ p=0.5 时 **±43.8pp**，单周胜负无统计意义；n=60（约 12 周）→ **±12.6pp**，观测 40% 与真值 50% 不可区分；压到 ±5pp 需 n≈385 ≈ **77 周交易**。生死判官仍是预注册判线（垫≥3× 双口径、FDR、前瞻 n≥20）。
